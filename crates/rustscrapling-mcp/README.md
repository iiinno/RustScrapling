# RustScrapling MCP (stage 7)

This crate uses the official Rust `rmcp` SDK and implements MCP over **stdio**. Start the standalone process with:

```bash
cargo run -p rustscrapling-mcp
```

The process reads newline-delimited MCP JSON-RPC requests from stdin and writes only protocol responses to stdout. Supported requests include `initialize`, `ping`, `tools/list`, and `tools/call`. It registers all **16 upstream tools**, preserving their names and help text. `make_request`, `session_make_request` and HTTP session management use `rustscrapling-http`. `browser_fetch_once`, `browser_open`, `browser_fetch` and session reuse use the CDP browser library. `browser_extract` supports Markdown/HTML/text, `browser_evaluate` supports explicit `isolated_context=false`, `browser_actions` supports waits, CSS-targeted single left click, CSS-targeted text input (including `textbox`'s default `clear=true` on native input/textarea), and a small set of keyboard keys; network tools offer captured summaries, response headers and bounded/redacted textual API response bodies.

Unsupported options or operations return `isError: true` with machine-readable `error.kind` (`unsupported_option`, `unsupported_operation`, `redirect_policy_unavailable`, etc.). HTTP sessions reuse connections but the current `HttpClient` lacks an automatic cookie jar. `browser_screenshot` returns PNG/JPEG image content for the viewport or full page (up to 8192 pixels per axis and 32 megapixels; 8 MiB encoded output). Screenshot element targeting via `selector`/`ref` remains unsupported. Browser actions only support plain CSS selectors (not ARIA refs, iframe targets or coordinate clicks), `click` with a single left click, `textbox(clear=false)` for appending or default `textbox(clear=true)` for replacing the value of native text-like `input` / `textarea` via CDP Ctrl+A/Backspace/insertText, `press_key` for Enter/Tab/Escape/Backspace/Delete/arrow keys, and `wait_time`. Non-text inputs, rich contenteditable controls, dialogs and other action shapes remain unsupported. ARIA snapshots/refs, IndexedDB, request bodies, general binary response bodies, and complete mouse/keyboard automation still require more CDP APIs. A default `follow_redirects="safe"` never follows 3xx redirects without the upstream private-IP verification; these requests return `redirect_policy_unavailable`. The upstream `google_search=true` browser default does not yet add a Google Referer. HTTP body decoding currently supports UTF-8. A browser `status=0` means the CDP layer did not capture an HTTP status.

### Browser network recording

`browser_network_requests` returns requests accumulated across page changes in one MCP browser session. Its IDs are strictly increasing session-local integers, **not** array indexes; evicting old records never assigns their ID to a newer request. `after_id` is an exclusive ID cursor, `next_cursor` is the last emitted ID (or the supplied cursor if no records match), `has_more` checks for further matching retained records, and `dropped_count` counts records evicted from the MCP history so far. It does not count upstream CDP events already dropped before being delivered to MCP. Each session retains at most **128 records** and **1 MiB of response body text**, with at most **64 KiB per body**. `limit` accepts integers 1–200 and IDs/cursors are bounded to JavaScript's exact integer range; invalid numbers are rejected. A dropped record can no longer be read by ID.

`browser_network_request(part="response_body")` now returns `available`, a `body` string when captured, `mime_type` and `size_bytes`; unavailable bodies carry an explanatory note rather than a fabricated value. This uses `BrowserPage::take_network()`, which performs the same bounded CDP capture and filtering as `BrowserPage::network_records()` and `search_network_bodies()`. Normal `browser_fetch` and subsequent network queries both ingest newly finished responses, without duplicating already consumed events. Only small textual XHR/Fetch bodies supported by the browser library are retained; its query/userinfo stripping, response-header allowlist and best-effort JSON credential redaction are preserved. These heuristics do not guarantee that arbitrary application data is free of secrets. `request_body` and `request_headers` remain unsupported, rather than falsely reporting complete upstream compatibility.

`browser_save_state` stores cookies and **the active top-level page's localStorage only** in RustScrapling state JSON version 2. Call `browser_fetch` on an HTTP(S) URL first. The save operation uses a CDP storage key obtained from the active page; loading verifies the saved origin matches that same page's origin before modifying state. Other origins, subframes, sessionStorage, IndexedDB, and full Playwright state are unsupported. Old version 1 cookie-only files remain loadable; unknown IndexedDB fields are rejected. Cookies and localStorage may contain login secrets. MCP accepts only filenames of the form `name.json` (alphanumerics, underscores, hyphens; 1–64 characters before `.json`) in a private directory: `%LOCALAPPDATA%/RustScrapling/browser-states` on Windows or `$XDG_STATE_HOME/rustscrapling/browser-states` (fallback `~/.local/state/...`) on Unix. Override this with `RUSTSCRAPLING_STATE_DIR`. It refuses traversal, absolute paths, symlink destinations, overwrites and files larger than 4 MiB. On Unix newly created files use mode `0600` and the state directory must have permissions `0700`; protect the configured directory with equivalent access controls on other platforms. Existing state files must be removed explicitly to save again under the same name.

The tool catalog is frozen in [`src/tools.json`](src/tools.json). It comes from the upstream BSD-3-Clause Scrapling source at fixed commit [`95cf9019ab5a5d6f3e9654b7ef1c6a26e29dc5c0`](https://github.com/D4Vinci/Scrapling/tree/95cf9019ab5a5d6f3e9654b7ef1c6a26e29dc5c0), including the parameter names, required/optional fields, Python defaults, help text, and the 12 discriminated browser action shapes. The source of truth is `scrapling/core/ai/server.py`, with types from `scrapling/core/_types.py` and `scrapling/core/ai/_browser_actions.py`.

To regenerate the snapshot, download those three upstream files at the same commit and invoke:

```bash
python crates/rustscrapling-mcp/tests/make_contract.py \
  <upstream-server.py> crates/rustscrapling-mcp/src/tools.json \
  <upstream-browser-actions.py> <upstream-types.py>
```

`cargo test -p rustscrapling-mcp` includes protocol-level tests that launch the binary, initialize through stdio, enumerate tools, and fetch from a local HTTP server through the real HTTP stack. Runtime tests also cover sessions and (when Chrome exists) CDP browser fetching. Native dependencies, including libxml2, are needed to build the workspace on the chosen platform.

**Remaining integration:** Full upstream `tests/ai/` behavioral parity requires more browser APIs, parameter handling and tests. Streamable HTTP MCP transport and the top-level `rustscrapling mcp` CLI entrypoint are separate tasks; this crate exports `serve_stdio(RustScraplingMcp::default())` for embedding in the single CLI binary.

# rustscrapling-extract

HTML article extraction for RustScrapling (Plan.md sections 3, 6.1, 6.2).

The crate reuses `rustscrapling-dom` and converts selected HTML with `htmd`.
It chooses a likely article/main/content subtree using visible body text,
meaningful paragraph counts and hyperlink density. A single bottom-up pass
computes those scores. The same exclusion rules apply to Markdown, plain
text and paragraph ranking.

```rust
use rustscrapling_extract::{extract, ExtractOptions};

let page = extract(
    "<main><article><h1>Release</h1><p>The release is ready.</p></article></main>",
    ExtractOptions { page_url: Some("https://example.org/news"), query: Some("release") },
)?;
println!("{}", page.markdown);
# Ok::<(), String>(())
```

`extract_dom` accepts an already parsed arena DOM. `markdown` is a
convenience wrapper. The serialized `ExtractedPage` contains `metadata`
(title, description, author, published/modified date, canonical URL, OG
properties and parsed JSON-LD), sanitized `html`, `markdown`, `text`,
`headings`, and `paragraphs` with stable source indices and BM25 scores.
The BM25 tokenizer uses lowercase words plus overlapping CJK character
bigrams, so Japanese queries work without spaces. Without a query,
paragraphs remain in document order with zero scores.

The sanitizer drops scripts, style, forms, embedded content, navigation,
sidebars, common advertisement/comment blocks, invisible HTML and inline
hidden styles. It reconstructs HTML from allow-listed elements and attributes;
link/image URLs permit only HTTP(S) or relative URLs, resolved against the
page URL when available. Source HTML is **untrusted data**. Visible prose can
still contain text crafted as an instruction to an AI agent; downstream
agents must treat extracted content as source material, never as commands.
The crate cannot evaluate external stylesheets or JavaScript-driven visibility;
sites that depend on those require browser-side rendering or computed-style
filtering before extraction.

`htmd` is provided under Apache-2.0; this crate contains no copied upstream
Scrapling implementation. The crate's own license is BSD-3-Clause.

Tests under `tests/` use three deterministic, hand-authored HTML fixtures for
article selection, metadata, markup safety, table/code fidelity and ranking.
These are **not** outputs from the pinned original Scrapling oracle. The
Plan.md requirement to compare word recall (at least 95%) and output size
against the original `main_content_only` still requires a fixture corpus
generated by the pinned Python oracle. It must be measured separately; the
fixture tests alone do not prove that threshold.
